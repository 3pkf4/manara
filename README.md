# المنارة POS & ERP — الإصدار 2.5

نظام نقاط بيع وإدارة متعدد المتاجر (SaaS): Node.js + Express + PostgreSQL، واجهة PWA تعمل بدون إنترنت.

## المتطلبات
- Node.js 18+  و PostgreSQL 13+

## التثبيت
```bash
npm install
cp .env.example .env          # ثم عدّل القيم
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # ضعه في JWT_SECRET
createdb manara_db            # أو أنشئ القاعدة والمستخدم بالطريقة المعتادة
npm run migrate               # يطبّق الهجرات ويطبع رمز الإعداد الأولي
npm start
```
افتح `/setup.html` وأدخل رمز الإعداد لإنشاء المتجر الأول وحساب المدير.
لحساب مالك المنصة (لوحة `/admin.html`): `npm run init-db` (كلمة المرور من `OWNER_PASSWORD` أو تُولَّد وتُطبع مرة واحدة).
وضع تجريبي ببيانات وهمية: `node server/database/init.js --demo` (مرفوض في production).

## الترقية من نسخة قديمة
1. **خذ نسخة احتياطية أولاً:** `npm run backup`.
2. ضع الملفات الجديدة ثم `npm run migrate` (أو يُطبَّق تلقائياً عند الإقلاع إذا `AUTO_MIGRATE=true`).
3. القواعد القديمة تُكتشف تلقائياً ويُعتبر 001–004 مطبّقة، ثم تُطبَّق 005 (تحويل التواريخ إلى TIMESTAMPTZ، عدّادات الترقيم، فهارس).
4. إن وُجد `local_id` مكرر في الفواتير يُنشأ الفهرس الفريد بعد تنظيفها يدوياً (يظهر تنبيه NOTICE).
5. **بدّل الأسرار** (`JWT_SECRET`، كلمات مرور القاعدة والمالك) إن كانت النسخة القديمة منشورة سابقاً.

## تغييرات السلوك المهمة
- تسجيل الدخول يتطلب **رمز المتجر** (tenant_code) عند وجود أكثر من متجر.
- كلمة المرور 8 أحرف على الأقل. خصم الكاشير الأقصى 10%.
- الاشتراك يُفعَّل بأكواد ترخيص تُستعمل مرة واحدة (مخزّنة مُجزّأة SHA-256).
- تغيير كلمة المرور أو الدور يُبطل الجلسات القديمة فوراً.

## العمل بدون إنترنت (جديد في 2.1)
- بعد تسجيل الدخول مرة واحدة على الجهاز وهو متصل، يفتح التطبيق ويعمل بدون إنترنت (الجلسة المحفوظة + لقطة المنتجات والعملاء).
- **البيع النقدي/البطاقة** بدون اتصال يُحفظ على الجهاز بمعرّف فريد ويظهر في شارة أعلى الشاشة («N معلّقة»). يُرسَل تلقائياً عند عودة الاتصال، ولا يتكرر لو أُعيد الإرسال.
- **حدود مقصودة:** تسجيل الدخول لأول مرة يحتاج اتصالاً؛ البيع الآجل غير متاح بدون اتصال (لا يمكن التحقق من سقف الدين)؛ الفاتورة التي يرفضها الخادم عند المزامنة (مثلاً نفد المخزون فعلياً) تبقى في القائمة مع سبب الرفض لتُراجَع يدوياً؛ بقية الصفحات (تقارير، فواتير…) تحتاج اتصالاً.
- الرسوم البيانية تحتاج تحميل Chart.js من الشبكة؛ بدونه تُخفى الرسوم فقط.

## الاستيراد والتصدير (جديد في 2.1)
صفحة `/data.html` (رابط «البيانات» في القائمة، وأزرار في صفحتي المخزون والعملاء):
- تصدير: نسخة JSON كاملة للمتجر، وCSV للمنتجات والعملاء والمبيعات والمصروفات وتقييم المخزون.
- استيراد المنتجات والعملاء والموردين من CSV (رؤوس عربية أو إنجليزية، أرقام عربية مقبولة) أو من JSON مُصدَّر، مع **معاينة بدون حفظ** وتقرير بالأخطاء حسب رقم الصف. التحديث عند التكرار لا يمس الكميات ولا أرصدة الديون.
- واجهات: `GET /api/data/backup` · `GET /api/data/template/:type` · `POST /api/data/import/:type`.
- استرجاع نسخة JSON كاملة (فواتير وحركات) غير مدعوم عمداً؛ الاسترجاع الكامل يتم من نسخة قاعدة البيانات `npm run backup` على الخادم.

## الباركود والمخزون المتقدم (جديد في 2.2)
- **الماسح الليزري/USB/بلوتوث:** يعمل كلوحة مفاتيح؛ في شاشة البيع يُلتقط تلقائياً حتى بدون الضغط على حقل البحث. الصيغة `5*باركود` تضرب الكمية.
- **كاميرا الهاتف:** زر 📷 في البيع وفي نافذة المنتج وصفحة المخزون. يستعمل BarcodeDetector (أندرويد/كروم) وإلا يعمل فك EAN-13/EAN-8/UPC-A مدمج. يحتاج https. (اختُبر على صور مولَّدة وليس على كاميرا حقيقية.)
- **باركودات متعددة** للمنتج (كرتونة = 12 حبة)، و**منع تكرار الباركود** في الفرع الواحد، و**توليد باركود داخلي** (EAN-13 يبدأ بـ29).
- **منتجات الوزن:** ملصق الميزان `2 + PLU(6) + غرامات(5) + تحقق` يضيف الكمية بالكيلو تلقائياً.
- **ملصقات** بمقاسات قياسية: EAN-13/UPC-A، وCode 128 لأي رمز نصي. ملصق EAN المُولَّد طابق مرجعاً مستقلاً وفكّه OpenCV.
- **صفحة `/inventory.html`:** الجرد بالمسح (تُطبَّق الفروقات عند الإغلاق ولا يضيع بيع جرى أثناء الجرد)، تسويات بأسباب (تالف/منتهي/فقد…)، سجل حركة، تحويل بين الفروع، اقتراح إعادة الطلب من معدل البيع.
- حدود: التحويل فوري (بلا حالة «في الطريق»)؛ الجرد يعتمد المخزون لحظة العدّ فأوقف البيع للصنف أثناء عدّه إن أمكن؛ لا يوجد بعد عروض/كوبونات/بطاقات هدايا.

## العروض واعتماد المدير (جديد في 2.3)
- **العروض**: من «المخزون ← العروض» (للمدراء) تُنشئ عرضاً بنسبة خصم أو بسعر ثابت على منتج أو تصنيف كامل، ولفرع أو لكل الفروع، بمدة محددة. يُطبَّق تلقائياً في الكاشير (السعر القديم مشطوب بجانب سعر العرض)، ويحسبه الخادم بنفسه فلا يمكن التلاعب به من الجهاز. عند تعدد العروض يُؤخذ الأقل سعراً.
- **اعتماد المدير**: إذا تجاوز الكاشير حد الخصم أو باع تحت الحد الأدنى للسعر تظهر نافذة تطلب اسم مستخدم وكلمة مرور مدير (مالك/مدير عام/مدير الفرع نفسه فقط)، فتُكمَل الفاتورة وتُسجَّل باسم من اعتمدها. كلمة المرور لا تُحفظ، والمحاولات الخاطئة محدودة (5 كل 10 دقائق).
- الاعتماد يحتاج اتصالاً بالخادم؛ بدون إنترنت تبقى الفاتورة المرفوضة للمراجعة في قائمة الانتظار.

## الدفع الإلكتروني للاشتراك — MyPay (جديد في 2.4)
1. في `.env` ضع `MYPAY_CLIENT_ID` و`MYPAY_CLIENT_SECRET` و`MYPAY_WEBHOOK_SECRET` و`PUBLIC_BASE_URL` (ابدأ بـ Sandbox ثم بدّل `MYPAY_BASE_URL` للإنتاج). لا تضع المفاتيح في أي ملف آخر.
2. في لوحة MyPay سجّل عنوان الإشعارات: `PUBLIC_BASE_URL/api/payments/webhook`.
3. من لوحة المالك (`/admin.html`) ← «أسعار الدفع الإلكتروني» حدّد سعر الباقات (أسبوعية/شهرية/سنوية). الباقة بلا سعر لا تظهر للعملاء.
4. عند انتهاء الاشتراك يرى مدير المتجر أزرار الباقات في نافذة القفل، فيُحوَّل لـ MyPay.
- **الأمان**: السعر من الخادم لا من المتصفح. الاشتراك لا يتجدد إلا بإشعار Webhook موقّع (HMAC-SHA256) يطابق الطلب في المبلغ والعملة، ويُحتسب مرة واحدة حتى لو تكرر الإشعار. صفحة العودة للعرض فقط. المبلغ المخالف يُعلَّم `mismatch` ولا يفعّل شيئاً.
- الأكواد اليدوية تبقى تعمل كما هي.

## واجهة الدعم للمالك (جديد في 2.5)
مسارات `/api/ops/*` محمية بمفتاح منفصل `OPS_API_KEY` (وليس كلمة مرور المالك)، تخدم لوحة Google Apps Script المرفقة في `manara-appsscript/`: ملخص، عملاء، تجديد/إيقاف، كلمة مرور مؤقتة عشوائية، مدفوعات، أكواد، وسجل تدقيق `ops_audit` باسم المنفّذ. معطّلة إن لم يُضبط المفتاح.

## النشر على الإنترنت
مجاني: `DEPLOY-FREE-AR.md` (Render + Neon + نسخ احتياطي عبر GitHub). مدفوع: `DEPLOY-AR.md` و`render.paid.yaml`. وأيضاً `Dockerfile` (VPS). `npm run preflight` يفحص إعدادات الإنتاج. يدعم `DATABASE_URL` وإنشاء حساب المالك تلقائياً عند أول إقلاع عبر `OWNER_PASSWORD`.

## النسخ الاحتياطي
`npm run backup` ينشئ نسخة مضغوطة ويحتفظ بآخر النسخ. جدولها بـ cron يومياً، وانسخها خارج الجهاز.

## التشغيل الدائم
`pm2 start ecosystem.config.js` — خلف Nginx أو Cloudflare Tunnel (`scripts/cloudflare-tunnel.sh`) مع `TRUST_PROXY=1`.

## التشغيل على الهاتف (Termux، أندرويد)
```bash
pkg install nodejs postgresql git
mkdir -p ~/pgdata && initdb ~/pgdata && pg_ctl -D ~/pgdata -l ~/pg.log start
createuser manara && createdb -O manara manara_db
# DB_HOST=localhost في .env ثم:
npm install && npm run migrate && npm start
```
للوصول من خارج الشبكة استخدم Cloudflare Tunnel. تنبيه: الهاتف ليس بديلاً مناسباً للخادم الدائم؛ الأفضل استضافة سحابية صغيرة.

## دخول الكاشير بـ QR (2.7)
المدير: المستخدمون ← زر ▦ بجانب الكاشير/أمين المخزن ← يظهر رمز QR. يمسحه الكاشير بكاميرا هاتفه فيدخل مباشرة ويُسجَّل جهازه تلقائياً.
- الرمز لمرة واحدة، صالح 10 دقائق، ويُخزَّن مشفّراً (SHA-256) في القاعدة.
- للكاشير وأمين المخزن فقط؛ مدير الفرع يصدره لفرعه فقط.
- الجلسة 7 أيام (`QR_SESSION_EXPIRY` اختياري). تعطيل المستخدم أو انتهاء الاشتراك يوقفه.
- الرمز في الجزء `#` من الرابط فلا يظهر في سجلات الخادم.

## أكواد التفعيل (بديل بوابة الدفع)
من لوحة Apps Script ← تبويب «الأكواد»: توليد أكواد (باقة + عدد + اسم العميل)، إرسالها بزر واتساب، نسخها، **إتلاف** غير المستخدم، وعرض المستخدم/المتلف.
- العميل غير الراغب بالدفع الإلكتروني يضغط في شاشة القفل «احصل على الكود عبر واتساب» (الرقم من `SUPPORT_WHATSAPP`، الافتراضي 218922227299) ثم يدخل الكود.
- الكود لمرة واحدة؛ يُحفظ في الخادم مجزّأً، ونسخته الأصلية في ورقة Codes في Google Sheet الخاصة بك فقط.
- API: `GET/POST /api/ops/license-codes`، `POST /api/ops/license-codes/:id/revoke`.
