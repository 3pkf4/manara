# النشر المجاني — Render (ويب) + Neon (قاعدة بيانات) + GitHub (نسخ احتياطي)

مناسب لـ: التجربة، وأول عملاء صغار. **ليس** كاستضافة مضمونة لمنتج تبيعه بالالتزام بالجاهزية. عندما تدخل أول إيرادات، انتقل للمدفوع (≈13 دولاراً شهرياً، راجع `DEPLOY-AR.md`).

## القيود الحقيقية للمجاني (اقرأها قبل أن تعد عميلاً بشيء)
| الجزء | القيد |
|---|---|
| Render المجانية | تنام بعد **15 دقيقة** بلا زيارات، وأول طلب بعدها ينتظر نحو دقيقة. وثائق/مراجعات تصفها بأنها ليست للإنتاج. 750 ساعة شهرياً تكفي خدمة واحدة تعمل طوال الشهر. |
| Neon المجانية | 1 جيجابايت تخزين. 100 ساعة-حوسبة (CU) شهرياً: عند نفادها يتوقف الحساب حتى الشهر التالي. تنام بعد 5 دقائق بلا استعلامات ولا يمكن تعطيل ذلك. |
| النسخ الاحتياطي | Render المجانية لا تحفظ بيانات؛ بياناتك في Neon، ونسخها بيدك عبر GitHub (خطوة 5). |
| الدعم | لا أحد يضمن لك وقت التشغيل. |

تقدير شخصي غير مُتحقَّق: متجر مفتوح 12 ساعة يومياً قد يستهلك نحو 90 ساعة-حوسبة شهرياً إن كان الحد الأدنى للحوسبة 0.25 CU. راقب صفحة Usage في Neon أول شهر.

**ما يحميك من النوم:** النظام يعمل بدون إنترنت ويحفظ مبيعات الكاشير ثم يرسلها، فلا يتوقف البيع إن نامت الخدمة؛ لكن يتأخر ظهور المزامنة.

## الخطوات

### 1) قاعدة البيانات (Neon)
1. https://neon.com ← سجّل بحساب Google/GitHub ← **Create project** ← المنطقة الأقرب (Frankfurt إن وجدت).
2. اضغط **Connect** وعطّل خيار **Connection pooling** (نريد الاتصال المباشر) ثم انسخ الرابط `postgresql://...?sslmode=require`. هذا سرّ: لا ترسله لأحد.

### 2) GitHub
كما في `DEPLOY-AR.md` الخطوة 1 (مستودع خاص `manara`، وأرسل لي اسمه لأرفع الكود بعد ربط GitHub بـ claude.ai).

### 3) Render
1. https://render.com ← سجّل بحساب GitHub (لا تحتاج بطاقة للخطة المجانية بحسب مصدر خارجي؛ إن طلبت منك فأخبرني).
2. **New +** ← **Blueprint** ← مستودع `manara` (الملف `render.yaml` للمجاني جاهز).
3. أدخل القيم: `DATABASE_URL` (رابط Neon)، `OWNER_PASSWORD` (قوية، أنت تختارها)، `OWNER_EMAIL`، وضع `-` في `PUBLIC_BASE_URL` وفي `MYPAY_*` الآن.
4. انتظر حتى **Live**، ثم اتبع خطوات «أول دخول» في `DEPLOY-AR.md` (تغيير كلمة مرور المالك، حذف `OWNER_PASSWORD`، ضبط `PUBLIC_BASE_URL`).

### 4) تخفيف النوم (اختياري)
في https://uptimerobot.com (مجاني) أنشئ Monitor من نوع HTTP على `رابطك/health` كل 5 دقائق. هذا يبقي الخدمة مستيقظة، ولا يوقظ قاعدة Neon لأن `/health` لا يستعلم القاعدة (فلا يستهلك ساعاتها). حلّ عملي غير مضمون: قد تغيّر Render سياستها.

### 5) نسخ احتياطي مجاني يومي
ملف `.github/workflows/backup.yml` جاهز. في المستودع: Settings ← Secrets and variables ← Actions ← أضف:
- `DATABASE_URL`: رابط Neon نفسه.
- `BACKUP_PASSPHRASE`: عبارة طويلة (16+ حرفاً) **تحفظها خارج GitHub**. بدونها لا تُفتح النسخة.

ثم Actions ← db-backup ← **Run workflow** للتجربة. النتيجة ملف مشفّر في Artifacts يُحفظ 30 يوماً. **نزّله أسبوعياً واحفظه خارج GitHub.** ولإرجاع نسخة (على جهاز فيه openssl وpsql):
```
openssl enc -d -aes-256-cbc -pbkdf2 -in manara-DATE.sql.gz.enc | gunzip | psql "رابط-قاعدة-جديدة"
```
جرّب الاسترجاع على قاعدة اختبار قبل أول عميل.

## الانتقال للمدفوع لاحقاً
لا تغيير في الكود: أنشئ قاعدة مدارة، انقل البيانات بالنسخة أعلاه، وغيّر `DATABASE_URL` وخطة الخدمة إلى Starter (والملف `render.paid.yaml` جاهز).

## ما لم يُجرَّب
لم أنشر على Render ولا Neon الحقيقيتين. اختبرت الإقلاع بـ `DATABASE_URL` محلياً، وخط النسخ الاحتياطي (تفريغ ← تشفير ← استرجاع) محلياً. اتصال Neon يحتاج SSL وهو في رابطها نفسه (`sslmode=require`)؛ وإن ظهر خطأ اتصال فأرسل لي سطر الخطأ من Logs.
